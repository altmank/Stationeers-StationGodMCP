One build, removal, swap or gas move by its id (place-41), or a script run (script-14): running, queued or finished. With no id: runs with notices pending (stopped or killed with something left, writes not done, or done and not yet seen).
Options:
- id (string or array): A job id (place-12, run-4, remove-3...), a script run (script-14), a gas transfer id, or "paste" (the last blueprint paste). Left out: the list above.
- max_wait (number, default 30): How long this reply waits, at most your client's timeout; the job or run goes on.
- verbose (boolean, default false): The whole job and preflight.
status: queued or waiting (not started yet), then applied, applied_with_differences, applied_unchecked, stopped or refused (jobs); queued, then applied or failed (gas moves). Only queued and waiting are not final.
A script run answers run_script's text block: script-N and its state (done, REPORT, stopped, killed, or running with the line and what it waits on), the returned value, and the footer so far, with its cost line.
On a live confirmed run it answers within 30 s, whatever max_wait says.
Any what that takes an id takes a list: one row per id, {results: [{index, ok, reference_id, payload | error}], count, success_count, error_count}, payload the one-id reply; a bad id is a row with error.
Reply: (a build or removal job) a BuildJob (help {topic: "types", subtopic: "BuildJob"}) | (a piece run) a RunJob (help {topic: "types", subtopic: "RunJob"}) | (a swap job) a SwapJob (help {topic: "types", subtopic: "SwapJob"}) | (an upgrade job) a UpgradeJob (help {topic: "types", subtopic: "UpgradeJob"}) | (an undo job) a UndoJob (help {topic: "types", subtopic: "UndoJob"}) | (queued) a JobQueued (help {topic: "types", subtopic: "JobQueued"}) | (a script run) text
Example: inspect {what: "job", id: "place-41"}
