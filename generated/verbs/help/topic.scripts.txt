A run is one call. A script changes nothing unless the run has confirm: true. confirm inside the code is refused: invalid_argument: confirm belongs to the run.
- What counts as seen (one rule for direct calls and scripts): ids the MCP server showed you this session (direct reply entries, report rows, a run's printed or returned value within its cut); any int or str constant in the run's code, f-string pieces included (a target passes when its value equals one of them); selectors written in the code (a network, a spread, a ref such as sg.ref('r7')); what this run builds (placed, swap results); "player".
- Report runs. run_script {code} reports every write (report_only: True), act-at-once writes included, and acts on nothing. The reply lists every target as [id or cell, name, current -> new], with its undo mark and any lifted guard (a very large report is summarised; past the client's limit it answers report_too_large). Builds report placed: [], so writes on what the run would build are not shown. Waits are real until the run's first write. After a write, the second wait inside a while or watch loop ends the pass with a BaseException, so finally runs and its writes are reported; finite for loops run through. One header line gives the report's limits: reads after a reported write show the old value; a waiting loop runs once; writes on what this run builds are not shown. for loops over found things list every target.
- Confirmed runs. run_script {code, confirm: true} acts as it goes on seen targets. An unseen target (such as ids a find inside the run returned that you never saw) before anything acted: the run goes on as a report run, and the reply is the report: unseen targets at line 7: nothing acted; this is the report; confirm it with run_script {repeat: "script-17", confirm: true}. After something acted: the run stops with sg.Stopped(unseen_targets, line, targets) before that write. After a stop the hub refuses the run's writes except held restores and writes in the finally or __exit__ it unwinds through (footered CLEANUP). The stop reply lists the remaining targets as report rows, so they are now seen, and says repeat (only undoable writes acted) or undo script-N first. A stopped run is not resumed.
- Repeat. run_script {repeat: "script-14", confirm: true} runs script-14's code again on fresh reads, under the same seen rule; the report's rows are seen. Logic values may differ from the report: the footer's DIFFERS FROM REPORT group shows them, and undo covers them. [cannot undo] writes (chip source, console command, screen press, uplink, flight log, trades, store moves) must have the whole argument set equal to the report's for that target, or the run stops. repeat_expired: the report was made in another world, or its record was dropped.
- Waiting. sg.wait(s) waits s seconds and returns None; time.sleep is sg.wait. sg.watch(reads, until, timeout) -> (rows, met): reads is a list of read logic reads entries ({'id': tank, 'logic': 'Pressure'}); until(rows) gets the rows, one per entry, in order, and returns a bool; rows is the last read. The watch ends when until returns True (met True) or after timeout seconds (met False); it never raises at timeout. It follows subscriptions where they cover the values, and otherwise polls once a second (light reads) or every 5 s (heavy ones). Repeating work (until X, or for N minutes) is one run with a loop: sg.watch, or a loop with sg.wait.
- Restores. with sg.hold(id, logic, value=None, after=<value before>): writes value, and restores after on exit (normal, exception or stop); the mod also applies it at session end or after an unresumed disconnect, in the same world and while the target still holds the run's last written value. Logic writes only, on seen targets. Reports show 'on exit: pump On -> 0'. It is the taught restore: plain finally runs on stops and run ends, but not at session end.
- A run is a job. max_wait is how long this reply waits (default 30 s for confirmed runs; up to the client's limit, 600 s, for report and read-only runs), at most your client's timeout; the run goes on until its code ends, it is stopped, or the session ends. A reply before the end says what the run waits on: script-14 running: line 4, sg.watch timeout 480 s, 37 s in, +3 write logic. Follow it with inspect {what: "job", id: "script-14"} (its own max_wait). inspect {what: "job"} with no id lists runs with notices pending.
- Notices. Notices and cost lines name the run's id and its first code line, and end "if you did not start it, leave it". A done notice comes once, on run_script and inspect job replies. A run that left something (stopped or killed with changes not restored, or writes not done) is one sticky line on every reply until you inspect it or undo it by id.
- Stop. server {what: "stop", id: "script-14"} stops one run; server {what: "stop"} stops every live run and answers the ids and first lines it stopped. A user cancel and the end of the session stop runs too. The run gets sg.Stopped (a BaseException: except Exception does not catch it) once, at its next sg call (at once inside a wait or watch), so finally blocks run: reads and writes still act there, waits and watches raise at once. The worker is killed 5 s after the stop (longer while an sg call is in flight, never past 30 s), or on a second stop. The stop reply lists what the run changed and did not restore (left: 4612280 On=1, set line 3) and each job in flight. A world change stops every live run and refuses later writes, finally included; held restores are dropped.
- The session. A run ends with this session; it is not a safety interlock; anything that must keep running belongs in a chip. A journal keeps each run's end state: the next session's first reply says in one line when something was left.
- Undo. undo {id: "script-14"} reverts the whole run, newest first, restoring each target to its value before the run; groups that cannot be undone are named [cannot undo]. A target changed since the run's last write (by the user, a chip or another run) is reported and not written unless allow: ["overwrite"]. It reports first; confirm: true undoes. Undo of a running run is refused: stop it first. After a world change it answers undo_expired.
- Warnings. A write on a device that a chip, logic writer, screen script or another run drives carries driven_by (inspect {what: "controllers", id} lists them); a vent, valve or pump opened runs the network lint. In a run they are gathered in the WARNINGS footer and report group. A run that re-reads a value it wrote and finds it changed lists it under CONTESTED.
- Cost lines. A run alive past its first reply has one line: calls, writes by verb and what, and game ms since the last line, and how to stop it. It rides every run_script, inspect job and server info reply, and other replies at most once every 10 minutes.
- The returned value. The code runs as a function body; return x, or a final bare expression. Past 4 KB the rest is in the run's ref; sg.ref('script-12') gives it as stored (a JSON round trip); sg.ref('r7') gives a direct reply as a dict, whole.
- Calls. Script calls mint no refs and are never cut. Iterating a reply dict raises TypeError: iterate r['things'] (the main list). The main list is walked by cursor in a single for; len, an index, sorted or a second pass pages in the rest first. offset is refused; limit is the first n in order. A script call waits for its job.
- Errors raise sg.Error(code, message, fix, maybe_ran). A failed run's reply gives: line N and its source; the exception and message; for sg.Error the call sent, code, fix and maybe_ran; for a KeyError on a reply dict, the keys it has, nearest first; the values of the names on that line; then the footer. print of a list of row dicts prints a table.
