A run is one call of verb calls: sg.<verb>('what', **options) is the direct call, with the same options and reply dicts, except that per-id whats always answer {results: [...]}, given one id or a list. Scripts are for waits, polls, timed or repeated writes and act-wait-act; for many targets a direct call with an id list is enough. A script changes nothing unless the run has confirm: true; confirm inside the code is refused.
- Seen (one rule for every write target, acted on or paid from): ids the MCP server sent you this session (replies after the cut, report rows, and a finished run's printed or returned value within its cut); int or str constants in the code, f-string pieces included (a target passes when its value equals one of them); selectors written in the code (a network, a spread, sg.ref('r7')); what this run builds; "player". The seen set is shared by every agent on this MCP server.
- Report run: run_script {code}. Nothing changes. Every target is listed as [id or cell, name, current -> new], with its undo mark, warnings and lifted guards; a build names a piece it would place by its cell (it has no id yet) and counts them in the report's placed, changed and kept (a confirmed job's log.placed names each). Waits are real until the first write; after a write, the second wait inside a while or watch loop ends the pass with a BaseException, so finally runs and is reported; finite for loops run through. One header line gives the limits. To act, send the same code again with confirm: true: the report's rows are now seen.
- Confirmed run: run_script {code, confirm: true}. Acts as it goes on seen targets. An unseen target stops the run with sg.Stopped (a BaseException). The reply says whether anything acted, lists the refused call's targets as rows (now seen), and gives the fix: "nothing acted: send it again with confirm: true", or "these acted: [...]; undo script-N first, then send it again". A stopped run is not resumed.
- After a stop (server stop, a write-rule stop, a user cancel or a world change), held restores and logic writes to targets the run already wrote still act, footered CLEANUP, until the kill (5 s after the stop, longer while a call is in flight, never past 30 s, or on a second stop). Writes to other targets answer an error row and do not raise, so the rest of finally runs. Waits do not raise after a stop. After a world change nothing acts.
- Restores: with sg.hold(id, logic, value=None, after=<value before>): registers after with the mod first, then writes value, and restores on exit; the mod also applies it at session end or after an unresumed disconnect, in the same world, while the target still holds the run's last written value. id may be a list; logic writes only. finally is best effort: it runs on stops and run ends, but not when the session ends.
- Waiting: sg.wait(s); time.sleep is sg.wait. Poll a sensor with read (a room or find query walks the world). sg.watch(reads, until, timeout) -> (rows, met): reads are read logic reads entries; until(rows) gets the rows in order; it never raises at timeout; in a report run it returns (current rows, True).
- A run is a job (script-N). A confirmed run answers within 30 s whatever max_wait says (max_wait may only shorten); a report or read-only run (no write or sg.hold in the code) waits up to the client's limit (600 s for Claude Code). A run past its reply answers script-N running: line 4, 37 s in, +3 write logic, 1.8 calls/s, 0.4 ms/s game. Follow it with inspect {what: "job", id: "script-N"}.
- Stop: server {what: "stop", id} stops one run; with no id, every live run, answering the ids and first lines. The run gets sg.Stopped once. The stop reply lists left: (changed and not restored) and each job in flight.
- Notices name the run's id and first code line and end "if you did not start it, leave it". A done notice comes on run_script and inspect job replies. A run that left something is one sticky left: line on every reply until you inspect it by id.
- Undo: undo {id: "script-N"} reverts the whole run, newest first, to the values before it. A target changed since the run's last write is reported and not written unless allow: ["overwrite"]. Undo of a running run is refused. After a world change: undo_expired.
- Calls: script calls mint no refs and are never cut. Iterating a reply dict raises TypeError naming its main list; a single for walks the main list by cursor, and len, an index, sorted or a second pass page in the rest. offset is refused; limit is the first n in order. A script call waits for its job.
- Errors raise sg.Error(code, message, fix, maybe_ran); only write-rule stops and stops are sg.Stopped. A failed run's reply gives the line and its source, the exception, the sg call with its code and fix, a reply dict's keys (nearest first), the values on the line, then the footer.
- The reply: state; returned value (return x or a final bare expression, 4 KB cut); printed output (4 KB cut); then the footer: writes by outcome, WARNINGS (driven_by, lint), PASSED, CONTESTED (a written value found changed), CLEANUP, undo with the classes, and the cost line (calls, calls/s, writes, game ms and ms/s, frames over budget, tick held, wall time).
