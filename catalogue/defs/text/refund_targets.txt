A list of targets tried in turn per item until it fits: "inventory" (the player's: from_id when it is a player, else the player; skipped without one), "source" (top up from_id when it is a stack, e.g. a coil), "storage" (from_id's slots, then the other slots of the container it is stored in), a container's reference id (exactly that container), "ground" (a metre in front of from_id or the player). Each target tops up matching stacks, then fills empty slots that take the item (never a hidden slot, a body slot or a stack's own slot); what fits none goes on the ground in front of the holder. Default ["inventory", "source", "storage", "ground"]. A target that cannot be used is skipped (refund_target_skipped when you named the list, saying why: no player; no from_id, from_id not a stack, from_id with no slot a refund could go into, or a from_id that names no thing). A from_id the same request removes is refused (refund_holder_removed) when refund_to gives into it (source, storage, the default). The dry run's refund_plan shows each item's destinations; the job's refunded entries name the target.
